---
title: Desktop client
description: Run Upstand in a secure native desktop shell.
---

Upstand Desktop is an Electron shell around an existing Upstand control plane.
It provides a native application window while retaining the same dashboard,
authentication, permissions, deployment history, and audit trail as the web
client. A new installation opens **Upstand Cloud** by default. The desktop-local
option is a local control plane with an embedded PGlite database. It does not
run Redis, Caddy, or a scheduler service; desktop starts the deployment worker
in-process and can build and deploy application images through the Docker
Engine installed on the workstation. Remote Docker servers remain supported
for workloads, monitoring, and Caddy request logs.

Desktop-local settings intentionally omit passkeys, email invitations, and
managed Git-provider integrations. Create workspace credentials directly;
for source checkout use a generic Git URL (or a local upload/Docker image).

## Connect

On its first launch, the app opens `https://upstand.dev`. Choose **Use this
computer** when you want the embedded bare control plane, **Use Upstand Cloud**
to return to Cloud, or enter the HTTPS origin of a self-hosted control plane.
The client accepts HTTP only for loopback addresses; remote instances must use
HTTPS.

The local desktop target requires a reachable Docker Engine. Deployment
concurrency is configured from **Observation → Deployments**; the setting is
stored for the local target and is honored by the in-process worker. If Docker
is unavailable, select a connected remote server instead.

The selected origin is persisted in the desktop application-data directory. Use
**Upstand → Change connection…** in the native menu to select another instance.

## Build installers

```bash
bun run --cwd apps/desktop make
```

Electron Forge produces platform-native installer artifacts. Windows uses a
Squirrel installer; macOS produces a ZIP archive; Linux produces Debian and
ZIP packages when the respective maker prerequisites are present. The DMG
maker is intentionally excluded because its upstream image parser has an
unresolved denial-of-service advisory.

## Security model

- The renderer is sandboxed with Node integration disabled.
- The preload bridge exposes only connection management, app version, GitHub
  release update operations, and explicit external-link operations.
- In-app navigation is confined to the configured control-plane origin.
- Links to other web origins open in the system browser; non-web schemes are
  rejected.
