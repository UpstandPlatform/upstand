# Upstand Docker Broker

`apps/docker-broker` is a high-performance, security-hardened Go proxy service that sits between the Upstand control plane (`server`, `schedules`, `deployment-worker`) and the host Docker daemon (`/var/run/docker.sock`).

It eliminates the security risk of mounting raw Docker daemon sockets into application containers by implementing least-privilege enforcement, mutual TLS (mTLS), per-caller identity tokens, HMAC-signed tenant scoping, and fine-grained Docker API command policy validation.

## Security Model

### 1. Zero Direct Host Socket Access
In standard Docker installations, giving a container access to `/var/run/docker.sock` provides root-equivalent control over the host. The Upstand Docker Broker runs with:
- `read_only: true` container root filesystem.
- `cap_drop: [ALL]` (all Linux capabilities dropped).
- `no-new-privileges: true` flag enabled.
- Dedicated unprivileged user (`10001:docker`).
- Internal network placement (`upstand-docker-control` Swarm overlay network with `--internal`), isolating the broker from public ingress and user-deployed containers.

### 2. Mutual TLS (mTLS)
All inter-service traffic over port `2375` is encrypted and authenticated using mutual TLS:
- A private Certificate Authority (CA) generated during Upstand installation signs broker and client certificates.
- The broker validates client certificates against `ca.pem`.
- Callers verify the broker server identity with TLS hostname checks (`docker-broker`).

### 3. Role-Based Caller Tokens
Every request must supply a valid Bearer token bound to an authorized caller role:
- **`server`**: Handles user-initiated manual tasks, configuration changes, and runtime queries.
- **`schedules`**: Handles scheduled health checks, cron triggers, backup runs, and monitoring scrapes.
- **`deployment-worker`**: Orchestrates container image builds, Git checkouts, Railpack pipelines, Swarm deployments, and rollbacks.

Tokens are provided via Docker secrets:
- `/run/secrets/docker_broker_server_token`
- `/run/secrets/docker_broker_schedules_token`
- `/run/secrets/docker_broker_deployment_worker_token`

### 4. HMAC-SHA256 Signed Scope Secrets
Mutating Docker operations (creating services, changing images, mounting volumes, attaching networks, copying files) require an HMAC-SHA256 signature generated by Upstand's core engine using `UPSTAND_DOCKER_SCOPE_SECRET`.
- Operations are cryptographically tied to the exact `organizationId`, `projectId`, `environmentId`, and `resourceId`.
- A compromised worker or tenant container cannot modify or delete another tenant's services or volumes.

### 5. In-Flight Concurrency & Payload Bounds
- **Concurrency Limiting**: Request slots are bounded (default: 64 concurrent in-flight requests, configurable between 1 and 256). Excessive requests receive `HTTP 429 Too Many Requests` with a `Retry-After: 1` header to prevent Docker daemon exhaustion.
- **Size Bounds**: Payloads (such as archive files or configs) are capped at `maxPolicyBody` (16 MiB).

## Capabilities & Enforced Policies

| Component | Responsibility & Policy Enforcement |
| :--- | :--- |
| **`caddy.go`** | Validates and dynamically reloads Caddy reverse-proxy routing. Blocks routes pointing to internal Docker control planes or unapproved external hosts. |
| **`inventory.go`** | Safely lists containers, services, networks, and tasks. Masks internal infrastructure containers and secrets from tenant-scoped queries. |
| **`monitoring.go`** | Collects real-time CPU, memory, network I/O, and disk usage for provisioned workloads without exposing host metrics. |
| **`network.go`** | Ensures services attach only to tenant-approved overlay networks and the shared gateway. Prevents bridge-mode container attachments to the internal control network. |
| **`resource_build.go`** | Safely controls image building, enforcing context limits and tag validation. |
| **`resource_convergence.go`** | Monitors Swarm service convergence during deployments with bounded deadlines, detecting crash loops and rollback triggers. |
| **`resource_files.go`** | Streams configuration and application archives into containers without writing arbitrary files to the host filesystem. |
| **`resource_rollback.go`** | Safely executes rolling updates and rollbacks to previous immutable task definitions. |
| **`resource_service.go`** | Creates, updates, scales, and tears down Docker Swarm services with verified resource limits (CPU/RAM quotas) and restart policies. |
| **`resource_volume.go`** | Restricts volume mounts to designated tenant persistent storage directories, preventing mounts to host system directories like `/etc`, `/root`, or `/var/run`. |

## Configuration & Environment Variables

| Variable | Description | Default |
| :--- | :--- | :--- |
| `UPSTAND_DOCKER_SOCKET` | Path to the local Docker daemon socket | `/var/run/docker.sock` |
| `UPSTAND_DOCKER_BROKER_CA_FILE` | Path to the CA certificate for client validation | `/run/secrets/ca.pem` |
| `UPSTAND_DOCKER_BROKER_SERVER_CERT_FILE` | Path to the broker TLS server certificate | `/run/secrets/cert.pem` |
| `UPSTAND_DOCKER_BROKER_SERVER_KEY_FILE` | Path to the broker TLS server private key | `/run/secrets/key.pem` |
| `UPSTAND_DOCKER_BROKER_SERVER_TOKEN_FILE` | Path to the Bearer token for `server` caller | `/run/secrets/docker_broker_server_token` |
| `UPSTAND_DOCKER_BROKER_SCHEDULES_TOKEN_FILE` | Path to the Bearer token for `schedules` caller | `/run/secrets/docker_broker_schedules_token` |
| `UPSTAND_DOCKER_BROKER_DEPLOYMENT_WORKER_TOKEN_FILE` | Path to the Bearer token for `deployment-worker` caller | `/run/secrets/docker_broker_deployment_worker_token` |
| `UPSTAND_DOCKER_BROKER_SCOPE_SECRET_FILE` | Path to HMAC-SHA256 secret for deployment scope signing | `/run/secrets/docker_broker_scope_secret` |
| `UPSTAND_DOCKER_BROKER_MAX_INFLIGHT` | Maximum simultaneous in-flight Docker daemon requests | `64` (bounds: 1-256) |

## Health & Diagnostics

- **Health Check Endpoint**: `GET https://127.0.0.1:2375/health`
  - Validates Docker daemon connectivity and broker socket state.
  - Used by Docker Swarm healthchecks:
    ```bash
    wget --no-check-certificate --quiet --spider https://127.0.0.1:2375/health || exit 1
    ```

## Development & Testing

### Running Unit Tests
Tests do not require a live Docker daemon; comprehensive mocks validate scope signatures, token checking, network policy enforcement, and Caddy synchronization.

```bash
cd apps/docker-broker
go test ./...
go test -race ./...
go vet ./...
```

### Building the Production Container
The broker is built with `CGO_ENABLED=0` as a statically linked binary:

```bash
docker build -t upstand-docker-broker:local -f Dockerfile .
```
